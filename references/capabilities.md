# capabilities.md · 能力发现、宿主适配与降级

读这份文件的时机：S0 初始化时；任何一步准备调用地图、天气、图片、生图、TikHub 之前；用户问"你能不能查 XX"时。

## 1. 先看有什么，再决定怎么做

初始化时只检查**当前宿主暴露的能力清单**，逐项记录到 `trip.json` 的 `capabilities[]`（结构见 `assets/schemas/README.md` → CapabilityReport）。

| capability | 检查什么 | 典型降级 |
| --- | --- | --- |
| `web_search` | 有没有联网搜索工具 | 没有 → 只用用户资料做草案，标"未完成实时核查" |
| `web_fetch` | 能否读取网页正文 | 没有 → 搜索摘要只能作线索，不能作事实依据 |
| `file_read` | 能否读用户给的文件/图片 | 没有 → 请用户粘贴文字内容 |
| `file_write` | 能否在工作目录写文件 | 没有 → 只交付方案文本，明说无法生成文件 |
| `script_exec` | 能否运行 Python 脚本 | 没有 → 模板路径 + 逐项人工复核，标"自动校验未执行" |
| `map_route` | 宿主是否有地图/路线工具且已获准 | 没有 → 三层降级（见 §3） |
| `weather` | 宿主是否有天气工具或可读可靠天气页 | 没有 → 天气占位 + 季节参考 + 待查事项 |
| `image_fetch` | 能否搜索/下载图片并核对许可 | 没有 → 文字版，不放图 |
| `image_gen` | 宿主是否有生图能力 | 没有 → 尝试本地排版与 PNG 导出；无法出图就明确说明，不要求新开账号 |
| `secret_store` | 有没有安全的凭据配置方式 | 没有 → TikHub 允许跳过，⛔ 不要求用户明文发令牌 |
| `tikhub` | 用户是否已配置 `TIKHUB_API_KEY` 且同意使用 | 未配置/未同意 → 普通联网调研 |

每项记：`availability`（available / unavailable / unknown）、`permission`（granted / denied / unknown / not_required）、`tool_id`（宿主里的工具名）、`verified_at`、`test_result`、`fallback`。

规则：

- **"存在工具"≠"已授权可用"**。只有在本次行程中实际调用成功，才能在交付里说"该来源已使用"。
- ⛔ 不扫描无关目录、不读取其他凭据、不为了探测能力发起付费请求（TikHub 的"连通测试"必须是第一次有用的查询，并计入已同意的预算）。
- `unknown` 是合法状态：不确定就写 unknown，并在需要用到时再试一次。
- 不同宿主（Claude Code、Cowork、其他兼容 Agent Skills 的宿主）工具名不同，把映射放在这里，不写死在流程里。

## 2. 五种运行条件

| 运行条件 | 可交付范围与处理方式 |
| --- | --- |
| 联网 + 文件写入 + 脚本执行 | 完整推荐路径；自动校验并生成 MD + HTML |
| 联网 + 文件写入，无脚本 | 用 `assets/templates/` 的固定模板输出，逐项复核；不得声称脚本校验已通过 |
| 文件写入，无联网 | 只用用户提供的资料生成草案，标"未完成实时核查"，保留待确认事项 |
| 只有对话 | 可以提供方案文本，明确无法完成文件交付；不伪造下载链接、不说"文件已生成" |
| 没有地图 / 天气 / TikHub / 生图 | 不阻塞基础规划；分别启用资料估算、天气占位、普通联网调研、跳过图片 |

面向小白用户，完整路径的目标环境是"有文件写入与联网、宿主自带脚本环境"。⛔ 不要为了跑脚本让用户去装 Python、npm 或任何依赖；脚本全部只用 Python 标准库，跑不了就走模板路径。

## 3. 地图与路线：三层渐进降级

**第一层：宿主现有工具。** 查当前宿主已经提供并获准使用的地图、路径规划、浏览器等能力。用户自己已经配置好的可以用；⛔ 不新增注册、不自动安装插件、不要求为基础功能另买服务。

**第二层：联网公开资料。** 读地图或运营方的公开页面、景点交通说明、公共交通站点信息、可访问的路线结果页。动态网页读不出来就明说不足；不绕过登录或访问限制。

**第三层：已有资料 + 保守估算。** 依据真实查到的片区、站点、同向关系和交通常识安排顺序，给**时间范围**并写明估算依据。关键路段连保守上界都建立不了 → 保留宽松结构或可选分支，⛔ 不宣称整个日程已验证可达。

每个路段（`TravelLeg`）必须记：起终点 ID、入口/站点、交通方式、查询时段、时间下界与上界、步行/换乘情况、来源、获取时间、`evidence_level`、不确定说明。

`evidence_level` 四档：

| 值 | 含义 | 时间表上怎么写 |
| --- | --- | --- |
| `tool_route` | 宿主地图工具返回的路线结果 | "约 25—35 分钟（地图工具，查询于 X）" |
| `public_route` | 公开路线页/运营方说明 | "约 30—45 分钟（官方交通说明）" |
| `estimate` | 基于片区、站点、直线距离的估算 | "预计 30—45 分钟，按 45 分钟留时（估算）" |
| `unknown` | 没有依据 | 不填时间；该衔接标 unknown，下游行程项降为 conditional |

规则：

- A→B 不自动等于 B→A；高峰/非高峰、公交/自驾不共用结果。
- 只有坐标或直线距离时，可以辅助分片区，⛔ 不能冒充道路距离或直接推导可执行时长。
- 没有真实地图也可以交付地点顺序，不强制画地图。
- 地名必须含足够的城市、分馆、入口信息，避免同名地点串线（见 `research.md` §5 消歧）。
- 导航按钮只用**已获得并验证**的链接；没有就给可复制的地点全称与地址，⛔ 不构造未验证的"精确路线链接"。
- `unknown` 不能被程序转成 0（`validate_trip.py` 会拦）。

## 4. 天气

优先用宿主天气工具或可靠天气页面。日期在实际预报覆盖范围内时，记地点、发布日期、有效时段、来源，并据此调整户外安排（雨天、酷热等）。

- 预报范围由提供方决定，⛔ 不能统一假定任意未来日期都可查（常见公开接口默认 7 天、最多约 16 天，具体以实际提供方为准）。
- 超出预报范围 → 提供明确标为"季节参考"的准备建议，⛔ 不伪造逐日温度。
- 获取不到天气不阻塞行程，加入待查事项。
- 已知官方关闭或显著天气风险时，相关活动不得留作确定安排。
- 出发前复核写进清单，由用户再次发起；⛔ 不默认建定时任务，不承诺自动监测。

`itinerary.weather.kind` 三档：`forecast`（真实预报）/ `seasonal`（季节参考）/ `unavailable`。

## 5. 图片与生图能力

- `image_fetch` 可用时，只用许可明确的图片（用户自己的、开放许可素材、明确允许使用的官方图），逐张记录原始页面、作者、许可、署名要求、用途。图片来自官方页面 ≠ 可以自由转载；小红书 API 返回的图片地址 ≠ 转载许可。许可不清楚 → 只留来源链接，不下载嵌入。
- `image_gen` 可用时可生成无字视觉素材；不可用时仍可展示现成的风格选择图，并优先用本地排版生成 1:5 PNG。无法导出时明确长图未完成，⛔ 不要求用户为基础规划新开账号。
- 生图有宿主费用时，纳入"费用授权"，先告知数量与可能费用。

## 6. 宿主薄适配层

把宿主特有的东西集中在这里，核心流程只认能力名：

| 能力名 | Claude Code / Cowork 常见对应 | 其他宿主 |
| --- | --- | --- |
| web_search / web_fetch | WebSearch / WebFetch | 按宿主工具清单填 |
| file_read / file_write | Read / Write / Edit | 同上 |
| script_exec | Bash（`python3 scripts/...`） | 同上 |
| map_route | 仅当用户已接入地图类 MCP 或浏览器工具时 | 同上 |
| image_gen | 用户已配置的生图 Skill/MCP（例如 baoyu-image-gen） | 同上 |
| secret_store | 宿主安全配置 / 本地环境变量 | 同上 |

自然语言触发依赖宿主是否实际安装、发现并加载本 Skill，⛔ 不承诺"在任意 AI 软件里说一句话就必然激活"。
